# 规格总纲（spec/00）

> 本文档是新引擎的**实现依据**。实现者（包括未来的你）只读 `spec/` 与 `acceptance/`，
> 不读原 Walimaker 源码。若某处规格不足，先补规格再写代码。

## 1. 目标

给**中小学课堂**提供一个"能让学生看见自己代码跑起来"的 2D 游戏引擎，基于
pygame（窗口/输入/绘制）+ pymunk（物理）+ pytmx（瓦片地图）。

具体目标，按重要性排序：

1. **零基础可用**：学生写十行代码就能让一个角色动起来；出错时给**中文**提示，
   并指出"错在哪、怎么改"。
2. **物理直觉正确**：重力、碰撞、约束、防高速穿透都要"看起来对"，
   不出现"明明撞上了却穿过去""停下后继续漂移"这类让人失去信任的现象。
3. **可教可讲**：模块划分与命名要能对应到课堂上的概念（对象、世界、刚体、精灵、图层）。
4. **可回归**：每次改动都要能用自动化测试证明"行为没变"（见 `acceptance/`）。

## 2. 非目标

- 不做 3D、不做联网多人、不做可视化编辑器（至少 v1 不做）。
- 不追求 3A 性能：目标规模是**课堂上几十个中小精灵**（贴图 ≤ 256×256，对象 ≤ 200 个）。
- 不做全平台打包工具（学生用 `pip install` 即可）。

## 3. 术语（课堂上怎么讲，代码里就怎么叫）

| 术语 | 含义 |
|---|---|
| 场景 / Scene | 一套独立的世界：物理空间、对象集合、相机、时钟。多个 Scene 互不干扰。 |
| 实体 / Entity | 场景里的一个东西：可能有贴图（显示层）、可能有刚体（物理层）。 |
| 贴图 / Visual | 显示层：单图、帧序列、状态机、或整张瓦片地图。 |
| 刚体 / Rigid | 物理层：圆 / 矩形 / 多边形 / 瓦片组，静态 / 动态 / 运动学。 |
| 相机 / Camera | 决定"看场景的哪一块"：跟随、缩放、抖动、死区。 |
| 步进 / Step | 固定物理步长 + 自适应子步（防穿透）。 |
| 图层 / Layer | 绘制顺序；同一位置谁盖住谁。 |

## 4. 兼容性目标（重要决策）

**接口保持兼容**：类名、方法名、参数形状尽量与课堂现有讲义一致
（`Character` / `Wall` / `Sensor` / `goto` / `velocity` / `scale` / `color` …），
这样学生手上的例子与老师的课件不用重写。

**实现完全独立**：内部结构、模块划分、数据结构、算法实现都重新设计，不沿用原项目的组织方式。

> 理由：接口与"能做什么"属于功能设计（思想层面），实现代码才是有版权的表达。
> 这是一条需要律师确认的判断，本文档把它显式记录下来，便于日后说明取舍。

## 5. 验收方式

1. **行为基线**（`acceptance/`）：一套固定场景 + 固定假时钟，记录若干观测值
   （位移/速度/碰撞/约束/子步/渲染像素哈希等），实现必须逐项对上。
   - 浮点比较用容差 `abs_tol=1e-3`；布尔/整数/字符串/像素哈希要求完全一致。
   - 基线由**同一套场景脚本**在新引擎上生成一次并冻结，之后任何改动都要对拍。
2. **规格测试**：`tests/` 里针对每条语义写断言（不是照抄旧测试，而是从规格写）。
3. **课堂可用性**：示例脚本能在无显示器环境（SDL dummy）跑完固定帧数不报错。

## 6. 新架构草案（与旧实现的组织方式不同）

```
src/pixelclass/
  __init__.py         公共入口：把常用名字一次性导出（`from pixelclass import *` 可用）
  vec.py              向量与坐标换算（屏幕坐标 ↔ 数学坐标，原点在窗口中心、y 轴向上）
  scene.py            Scene：物理空间、对象集合、相机、时钟、固定步进与子步
  entity/
    __init__.py       导出 Entity / Character / Wall / Sensor / Mouse 等
    node.py           基类：身份、变换（位置/旋转/缩放）、生命周期、组件挂载
    actor.py          行为层：运动命令、朝向、播放音效、对话
    presets.py        课堂预设：动态/静态/触发器/跟随鼠标
  visual/
    sprite.py         贴图载体：变换、着色、可见性、图层
    strategies.py     单图 / 帧序列 / 状态机 / 瓦片地图 四种绘制策略
  physics/
    body.py           刚体封装：形状、质量、摩擦、弹性、速度、力
    tiles.py          瓦片刚体组：按格子合并、邻居连接
    joints.py         约束：销钉、弹簧
  worldmap/
    tiled.py          TMX 解析：图层渲染、对象层 → 实体
  ui/
    textbox.py        文本与对话框
  help/
    errors.py         中英双语报错与 `sys.excepthook` 钩子
    fonts.py          中文字体查找（包内 → 系统 → 默认）
  audio.py            音效与背景音乐
  resources.py        图片/字体缓存（弱引用，避免泄漏）
```

与旧实现的主要差异（证明是独立设计，不是搬运）：

| 维度 | 旧实现 | 新实现 |
|---|---|---|
| 全局状态 | 模块级 `global_var` 单例 + 各组全局容器 | 显式 `Scene` 对象，构造时注入，不用全局 |
| 对象模型 | `Object` → `GameObject` 继承 + 三个 mixin | 组合：`Node` 持有 `Visual` / `Rigid` 组件，行为在同层方法里 |
| 刚体访问 | 继承链上层层代理 | 组件对象直接暴露，属性转发由 `Node` 显式声明 |
| 绘制策略 | 用类继承 + `Sprite.autos` 注册表 | 用字典显式映射输入类型 → 策略函数 |
| 时间 | 屏幕对象内部累积 | 独立 `Clock`/`Stepper`，可注入假时钟（便于测试） |

## 7. 里程碑

| 阶段 | 内容 | 完成标志 |
|---|---|---|
| M0 | 规格（本文档 + 02…09）+ 验收场景脚本 | 规格覆盖公开接口；验收基线可在旧引擎上生成 |
| M1 | `vec` / `scene` / 步进 / 渲染主循环 | 空场景能开窗、按固定步长推进、假时钟可控 |
| M2 | `visual` + `physics`（圆/盒/多边形/瓦片组） | 行为基线中"位移/速度/旋转/缩放/碰撞/子步"各项对上 |
| M3 | `entity` + 预设类 + 输入 | 课堂示例（角色跑跳、平台、触发器）行为对上 |
| M4 | `worldmap` 对象层 + `ui` + `audio` + `help` | 行为基线全绿 + 示例可跑 |
| M5 | 打包 / 发布脚本 / 文档 | 可 `pip install`、可发布到 PyPI（新名字） |
