# 01 坐标系、场景与主循环

> 实现依据。本文只描述**行为应当如何**；内部怎么实现由实现者决定。

## 1. 坐标系

- 对外一律使用**数学坐标**：原点在**窗口中心**，x 向右、y **向上**，单位像素。
- 屏幕坐标原点在左上、y 向下，只在绘制与鼠标事件换算时使用。
- 换算关系（`w`/`h` 为窗口宽高）：

  ```
  数学 (mx, my)  ->  屏幕 (sx, sy) = (mx + w/2, h/2 - my)
  屏幕 (sx, sy)  ->  数学 (mx, my) = (sx - w/2, h/2 - sy)
  ```

- 对外暴露两个互逆的换算函数（兼容目标的名字：`pygame2Cartesian` / `Cartesian2pygame`），
  并且可以带场景参数（多场景时按该场景的窗口尺寸换算）。

> 教学含义：学生说"往右上飞"就是 x 变大、y 变大；不会因为屏幕 y 向下而反直觉。

## 2. 场景（Scene）

一个**场景**是一套彼此独立的世界。它拥有：

| 组成 | 说明 |
|---|---|
| 物理空间 | pymunk 的 `Space`；重力、刚体、形状、约束都在这里 |
| 对象集合 | 场景里的所有实体（用于每帧更新与逻辑遍历） |
| 绘制集合 | 参与渲染的贴图，按图层排序 |
| 相机 | 看场景的哪一块（跟随、缩放、抖动） |
| 时钟 | 帧时间与固定步长累积（可注入，便于测试） |

### 2.1 生命周期

```
创建场景 -> setup(宽, 高) -> 每帧 update() -> done()
```

- `setup(宽, 高)`：若还没有窗口就创建窗口；初始化该场景的物理空间、对象集合、相机；
  **重力默认 (0, 0)**（学生必须显式设置才有重力，避免"为什么我的角色往下掉"的意外）。
- `update()`：推进一帧（见 §3）。可带场景参数，只推进指定场景。
- `done()`：结束主循环并关闭窗口。

### 2.2 多场景

- 对象只属于创建它的场景；推进/绘制某个场景不会影响其它场景。
- 需要场景的接口都接受一个**可选参数**（兼容目标的名字：`world`），缺省表示"当前场景"。
- 同一个程序里可以有多个场景（例如"地图场景"与"战斗场景"并存），各自的相机独立。

### 2.3 未初始化就使用

- 在 `setup()` 之前创建对象或调用需要窗口的接口，**必须**抛出**中英双语**的可读错误，
  指出"忘了先调用 setup()"以及怎么改（见 `04-errors-and-fonts`）。

## 3. 主循环与时间

### 3.1 固定步长

- 物理固定步长 `PHYSICS_DT = 1/60` 秒。
- 每帧把真实经过的时间累加进累积器，按整步消耗：
  **累积到不足一步时本帧不推进物理**（保证物理不受帧率影响）。
- 单帧累积上限 `MAX_FRAME_TIME`：超过就截断（避免断点调试后一次补上百步）。

### 3.2 自适应子步（防高速穿透）

- pymunk 没有连续碰撞检测：一步内位移超过碰撞体厚度就会**穿过去**。
- 每个固定步按"最快物体一步走多远"切分成若干子步：

  ```
  阈值 MAX_STEP_DISTANCE 默认 8.0 像素；上限 MAX_SUBSTEPS 默认 16
  最快速度 = 所有非静态刚体速度的模的最大值
  若 最快速度 × dt <= 阈值        -> 子步数 = 1
  否则 子步数 = clamp(floor(最快速度 × dt / 阈值) + 1, 1, 上限)
  子步执行 = 把 dt 平均切成 n 份，连续 step n 次
  ```

- 注意是**"向下取整再 +1"而不是"向上取整"**：恰好整除时也多切一步
  （例：`2400 px/s` 的子弹、`dt = 1/60`、阈值 8 → 商为 5.0 → 子步数 6），
  保证每个子步的位移**严格小于**阈值。验收观测 `max_substeps = 6` 就是这一条。

- `MAX_STEP_DISTANCE = 0` 表示**关闭子步**（恢复"会穿模"的旧行为，便于课堂对比演示）。
- 慢速场景子步数恒为 1：**行为与性能都不变**。

### 3.3 每帧顺序

```
处理输入事件
  -> 把刚体状态同步到显示层（写显示缓存）+ 实体/视觉每帧更新 + 相机跟随
  -> 推进物理（按累积器取整数个固定步，必要时子步）
  -> 绘制 -> 翻页
```

- **顺序是有意为之**：物理推进放在帧末，所以**本帧绘制的是上一帧物理的结果**。
  这样一次 `update()` 内不会出现"已经画过又被物理改写"的中间态；也意味着
  `update()` 之后读到的 `obj.pos` 比刚体位置**晚一个物理步**（验收观测 `fall_after_30`
  与 `tunnel_bullet_x` 就钉住了这一点）。

## 4. 不变量（跨模块，必须成立）

1. **物理每帧同步显示坐标 / 角度时，不得反向写回刚体**。
   回写会触发 pymunk 的宽相重排（`reindex_shapes_for_body`），每帧白烧 CPU。
   因此存在两条不同的写入路径（见 §5）。
2. **销毁对象后**：显示层与物理层都被移除，对象标记为不再存活；再次遍历时不得报错。
3. **速度语义**：直接写位置视作瞬移（清零速度）；增量位移不清速度（重力继续生效）。

## 5. 位置 / 角度的三条写入路径

| 路径 | 写显示缓存 | 写刚体 | 动速度 | 用途 |
|---|---|---|---|---|
| `pos = (x, y)` / `goto(...)` | 是 | 是 | **清零** | 摆放、传送、复活 |
| `shift_by((dx, dy))` | 是 | 是 | 否 | 按键位移、滑行动画 |
| `sync_pos(p)` / `sync_rot(r)` | 是 | **否** | 否 | 物理层每帧回写（内部用） |

- `rot = r` 同理：写缓存 + 重绘标记 + 刚体；物理层回写走 `sync_rot`。
- 为什么要有 `shift_by`：`Character` 一边受重力下落、一边被老师用 `forward()` 推着走时，
  不能因为推了一下就把下落速度清掉。

## 6. 验收（对应 `acceptance/`）

- 固定假时钟下，自由落体 30 帧后的位置与速度必须与基线一致。
- 高速子弹（2400 px/s）打向薄墙（8 px）不得穿透；记录本场景的最大子步数。
- 多场景：推进场景 A 不得改变场景 B 里对象的位置与速度。
